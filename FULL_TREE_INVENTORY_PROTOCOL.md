# Exhaustive source-tree inventory protocol

**Registered in repository:** 2026-10-10 (Asia/Bangkok)  
**Status:** Exploratory extension to the frozen corpus audit; executed only
against the same pinned `openai/math` commit.

## Purpose

The original preregistered audit measures the catalogue-linked corpus defined
by `CONTENTS.md`. This extension answers a distinct coverage question: what
files are present in the entire immutable Git tree of the same public release?
It does not replace or alter the original RQ1--RQ3 estimands, statistical
test, or surrogate-model protocol.

## Inclusion and unit

The inclusion set is **every Git blob returned by**
`git ls-tree -r -l -z fd4aeeb2ee4fc729c18d98444fed42fd0529eeeb` in the
verified, pinned `openai/math` checkout. The pipeline rejects a checkout whose
`HEAD` is not that commit, resolves that commit once, and uses the resolved
immutable ref for every subsequent Git object read. Its tree identifier is
recorded in the derived manifest.
The unit is one path/blob pair. This includes research artifacts, build
metadata, documentation, and support files, so that the coverage denominator
is explicit rather than inferred from the catalogue. Git trees cannot contain
two blobs at the same path in one commit; the implementation nevertheless
checks path uniqueness.

## Frozen measurements

For every blob, the analysis records its path, Git blob object identifier,
Git-recorded byte size, top-level directory, extension, deterministic
path/extension-based artifact role, and membership in a catalogue-linked
preprint directory or named released summary. It reports counts and bytes by
top-level directory, artifact role, and extension, plus the number of unique
blob object identifiers.

Artifact roles are a transparent structural classification, not an assertion
about file contents or mathematical value. The classifier recognizes root
release metadata, Lean scope documents, Lean sources, Lean metadata/support,
preprint PDFs, TeX sources, bibliographies, preprint support files, released
reasoning-summary PDFs, and residual files. Every blob receives exactly one
role.

## Checks and interpretation limits

The extension fails if the checkout is unpinned or fails `git fsck`, if the
tree is empty, if a path repeats, if a blob identifier is malformed, if bytes
are negative, or if the output inventory does not contain exactly the tree's
blob count. It does not parse every mathematical statement, compile the Lean
project, validate a PDF, infer provenance beyond the pinned public tree, or
identify model internals. A complete tree census is therefore evidence of
release coverage and organization, not evidence that every file was
semantically understood, correct, or generated by a particular mechanism.

## Outputs

`python -m oai_math_study.run_analysis` regenerates:

- `data/derived/full_tree_inventory.csv` -- one metadata row per release blob;
- `data/derived/full_tree_summary.json` -- aggregate counts, bytes, and
  validation evidence; and
- `figures/full_tree_composition.{pdf,png}` -- a log-scale structural summary.

The CSV contains derived metadata only; the third-party source tree remains
under ignored `external/` and is never copied into this repository or the
arXiv source archive.
